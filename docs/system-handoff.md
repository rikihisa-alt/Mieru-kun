# てんぽみえるくん — システム引き継ぎ資料（AIタスク管理用）

このドキュメント1枚で、システムの目的・現状・残タスクを把握できるようにまとめています。
別のAI/担当者がタスク管理する前提の自己完結ブリーフです。最終更新: 2026-07-13

---

## 1. これは何のシステムか（目的）

**「てんぽみえるくん」= アミューズメントカジノの店舗運営管理システム（Webアプリ / SaaS）。**

ポーカールーム/アミューズメントカジノの日々の店舗運営を、1つの管理画面に集約する。
これまでスプレッドシートや紙で行っていた各種管理を可視化・自動化するのが狙い。

### システムが担う目的
| 目的 | 概要 |
|------|------|
| 顧客管理 | 会員情報（本名/ポーカーネーム/電話/誓約書番号/誕生日/来店回数/チップ/ポイント/コメント）。表示は原則ポーカーネームのみ（本名は店側だけ） |
| 入店管理 | QR/LINE誘導でチェックイン。初回は年齢確認・誓約書・ルール説明を必須化 |
| 卓管理 | 卓のビジュアル配置、着席管理、ディーラー配置/交代/持ち時間タイマー、ウェイティングリスト |
| 注文・売上管理 | レジ精算、料金カテゴリ（エントランス/トナメフィー/チップ貸出/フード・ドリンク/その他）、後払い（売掛）と未払い消し込み |
| チップ管理 | 客ごとの保有チップ、日/週/月/年・曜日別・ゲーム別の増減をグラフで可視化 |
| 従業員管理 | 登録/勤怠/シフト/簡単な人事 |
| SNS運用・販促 | 曜日別POP・投稿テンプレ・画像ストック（半自動運用）、ポイント→ランキング施策 |
| LINE連携 | 顧客の会員登録・マイページ・店内状況確認、スタッフのモバイル業務。※現状はUIのみ（後述） |

---

## 2. どう運用していきたいか（運用ビジョン）

- **1つの管理画面（iPad/PC）で店舗運営を完結**させる。スタッフが迷わず使えるUIを重視。
- **客はLINEから**会員登録・予約・店内状況確認・注文・自分のランキング確認ができる。
- **スタッフはスマホ/店内タブレット**から出退勤・注文取り・卓確認ができる。
- **店内サイネージ（大画面）**に卓状況やトナメのブラインドタイマーを表示。
- **オーナーはデータで経営判断**（売上予実・チップ収支・顧客分析・月次損益）。
- 導入は段階的（まず卓管理+入店 → 注文 → 精算…と広げる想定）。

## 3. 技術構成と重要な制約（AIが必ず把握すべき前提）

| 項目 | 内容 |
|------|------|
| フレームワーク | **Next.js 16（App Router）+ React 19 + TypeScript**。※`AGENTS.md`に「通常のNext.jsと異なる。node_modules/next/dist/docs/ を読め」との注記あり |

| ⚠️ 開発環境の罠 | リポジトリの**絶対パスに日本語**が含まれるため、**Turbopack（`next dev`）が起動時クラッシュ**する。ローカル確認は **`next dev --webpack`** を使う |
| デザイン基準 | **`docs/ui-standards.md`**（全ページ準拠）。トークン: `src/app/k4z8qm3x/v2.css`（`.v2`スコープ）、`src/app/(line-customer)/line.css`（`.ln`スコープ） |

## 5. これからのタスク（優先順）

### 🔴 最優先（オーナーの準備が必要 → 着手待ち）
1. **Supabase接続（DB化）** — localStorage → 実DB。これが全ての土台。依存する解禁事項:
   - 複数端末間のリアルタイム同期（レジPC↔ホールiPad↔スタッフスマホ）
   - LINEページ・スタッフページの実データ化
   - QRカメラ読取での入店照合
   - **本番ログイン認証**（現状デモ素通り）+ 権限ロール(オーナー/店長/スタッフ)
   - 要: Supabaseプロジェクト作成、環境変数(`NEXT_PUBLIC_SUPABASE_URL`/`ANON_KEY`)設定、スキーマ設計、localStorageからの移行

### 🟠 次点（DB接続後）
2. **LINE連携（LIFF / Messaging API）** — 実際にLINEから使えるように。要: LINE公式アカウント/LIFF設定
3. **LINE Push配信** — 誕生日/来店促進/イベント告知のセグメント配信（集客の肝）
4. **QRカメラ読取** — 会員QR照合入店（zxing等。ライブラリ未導入）

### 🟡 仕様・データ待ち
5. **スプレッドシート移行** — 現行シートの棚卸し→対応付け→CSV取込。要: 現在使っているシートの共有
6. **SNS自動投稿の作り込み** — 半自動運用の完成。要: X API有料枠 or オープンチャット制約の判断（現状はテンプレのワンタップコピー+投稿記録）

### 🟢 整理・追加（外部依存なし、着手可能）
7. **旧管理画面(manage 38ページ)の廃止 or リダイレクト整理** — 二重管理の解消
8. **バックアップ/データエクスポート** — 全データの定期バックアップ（DB化後）
9. 追加機能候補: ウェイティング→LINE呼出通知 / 多店舗横断ダッシュボード / トナメのイベント/カレンダー起票連携の双方向化

## 7. 作業時の注意（重要な学び）
- **UI変更は「見切れ・はみ出し・重なりゼロ」を必ず検証**（過去に卓の席配置で実測不足の手戻りが多発）。座標系はpx/%の混在に注意。可能なら `next dev --webpack` で実ブラウザ実測。
- **CSSの詳細度に注意**（`.v2 button{padding:0}` のリセットが `.v2-btn` に勝つ等の落とし穴あり。`.v2 .v2-btn` のようにクラス2つで上げる）。
- コミットは日本語メッセージ、mainへ直push即デプロイ。変更後は該当ページの確認URLを提示する運用。
