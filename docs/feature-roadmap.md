# てんぽみえるくん 機能完成ロードマップ

## システムの目的 (オーナー確認済み 2026-07-09)

**アミューズメントカジノの店舗管理システム。**

| 目的 | 対応する本リストの領域 |
|------|------------------------|
| 顧客管理 | A-7 顧客 / B. LINE顧客ページ |
| 売上管理 | A-4 注文・精算 / A-10 売上 / A-12 締め / A-13 集計 |
| 入店管理 | A-2 入店 / E-3 会員証QR |
| 卓管理 | A-3 卓管理 / E-1 トナメ管理 / E-2 ウェイティングリスト |
| 注文管理 | A-4 注文・精算 / A-5 ライブ注文 / B-11 注文・呼出 |
| SNS運用管理 | **F. SNS運用管理 (新規領域)** |
| 従業員管理 | A-8 従業員 / A-9 勤怠 / C. LINEスタッフページ / E-7 シフト管理 |
| LINE連携による広告・販促 | D-3 LINE連携 / E-4 LINE配信 / A-16〜19 施策 |
| スプレッドシート業務の可視化 | **G. スプレッドシート業務の移行 (新規領域)** |

実店舗導入を目標に、機能ごとに仕様を詰めて完成度を上げるためのリスト。
凡例: ◎=実用レベルに近い / ○=UIあり・仕様の詰めが必要 / △=デモ固定(見た目のみ) / ✕=未実装

> 現状の全体像: ほぼ全ページが localStorage デモで動作。Supabase は環境変数未設定のため実DBは未接続。

## D. 共通基盤 (実店舗導入の前提条件)

| # | 項目 | 現状 | 必要な作業 |
|---|------|------|-----------|
| D-1 | データベース (Supabase) | 環境変数がプレースホルダーで未接続。全データがlocalStorage | スキーマ設計→接続→各ストアのDB化。localStorageからの移行 |
| D-2 | 認証・権限 | ログインUIのみ(実質素通り) | Supabase Auth本接続、ロール別アクセス制御(RLS) |
| D-3 | LINE公式アカウント連携 | ページUIのみ。LIFF/Messaging API未接続 | LIFF ID取得、LINEログイン、リッチメニュー設計、Push通知 |
| D-4 | 複数端末同期 | BroadcastChannel(同一ブラウザ内のみ) | DB化(D-1)により自動解決。リアルタイム反映はSupabase Realtime |
| D-5 | 旧管理画面 ((manage) 38ページ) | v2と二重管理状態 | v2へ一本化し旧ルートは廃止 or リダイレクト(要判断) |
| D-6 | バックアップ・エクスポート | なし | 日次バックアップ、CSV出力 |
| D-7 | 操作ログ・監査 | なし | 金銭・チップ操作の全記録ログ(A-15と統合) |

## 推奨の進め方

1. **仕様を詰めるフェーズ (機能ごとに対話で決める)** — 本リストの上から順ではなく、店のオペレーションの流れで:
   「入店 → 卓 → 注文 → 精算 → 締め」の基幹フロー (A-2,3,4,10,12) を最初に確定
2. **共通基盤 (D-1,2)** — 基幹フローの仕様が固まった時点でDB設計に着手 (先にDBを作ると手戻りする)
3. **LINE連携 (D-3 + B/C)** — 管理画面側の実データができてから接続
4. **施策系 (A-16〜19, E-1〜8)** — 基幹が回ってから
