## 確定仕様 (オーナーヒアリング 2026-07-09)

### 顧客管理 (→A-7)
- 管理項目: **名前 / ポーカーネーム / 電話番号 / 誓約書管理番号(電子サイン不要・番号記載のみ) / 来店回数 / チップ数 / 誕生日 / コメント** 等
- 登録経路は2つ: ①LINE誘導で顧客自身が登録 ②従業員が管理画面から直接入力 — どちらも**会員IDで一元認識**
- 客同士に見える表示は**ポーカーネームのみ**(本名は店側のみ)

### 入店管理 (→A-2)
- チェックイン方法: **QRコード** / **LINEからの誘導ページ**
- チェックインすると店内状況(B-8)に反映される

### LINE顧客ページ (→B)
- LINEからの誘導で**店内状況**(誰が=ポーカーネームのみ・どの卓で・何をしているか)と**イベント内容**が見られる
- 自分の**ランキング**を確認できる(ポイント制)

### 売上管理 (→A-4 / A-10)
- 料金カテゴリ: **エントランス / トーナメントフィー / チップ貸出料 / フード・ドリンク / その他**
- 金額は**マスタで事前設定**と**直接入力**の両対応
- 全売上を**来店客・予約客に紐付け**
- **後払い対応**: 上限なし。未払いのリスト化と消し込み処理。ダッシュボードから未払いリストを閲覧できること (2026-07-09確定)

### 卓管理 (→A-3)
- 卓は**長方形**を基本とし(※現状は楕円 → 変更)、事前に設定した卓を**フロア上でドラッグして直感的に移動**(自由配置)
- 客の移動はドラッグ + クリック→サブメニュー(実装済)
- ディーラー配置・交代(実装済)

### 注文管理 (→A-5 / B-11)
- 客が**LINE誘導ページから注文** → 管理画面(iPad/PC想定)に**リアルタイム通知**
- 通知には**卓番号・席番号・ポーカーネーム**を表示
- **後払い**(会計へ積む)対応
- 対応完了後の**消し込み**

### SNS運用管理 (→F)
- **曜日ごとに行っているPOPの設定・画像の貯蔵**
- **ツイート内容のテンプレ管理・自動投稿**
- **LINEオープンチャットへの自動投稿**
- 投稿方式は**半自動運用で確定**(テンプレをワンタップコピー+投稿時間リマインド)。X API有料枠・オープンチャットBot不可のため
- 卓管理の**フロア自由配置も確定**(縦一列リストを廃止し、フロアマップ上に卓をドラッグ配置)

### ポイント・ランキング (→A-16 / A-21)
- ポイント付与対象: **来店 / 購入 / トーナメント入賞(ITM)** 等
- ポイントでランキング化し、客はLINEから自分の順位を確認できる

### 従業員管理 (→A-8 / A-9 / E-7)
- **従業員登録 / シフト作成 / 簡単な人事労務 / 出退勤管理**
- 出退勤は**LINEからの打刻・QRコード打刻**を想定

### チップ管理 (→A-14)
- 客ごとの**現在保有チップ数**
- **全体チップの増減を日 / 週 / 月 / 年**で集計
- **ゲーム(卓種別)ごと**の増減、**曜日別**などの多角的な分析軸
- **グラフによるビジュアル表示**

> 現状の全体像: ほぼ全ページが localStorage デモで動作。Supabase は環境変数未設定のため実DBは未接続。

## 推奨の進め方

1. **仕様を詰めるフェーズ (機能ごとに対話で決める)** — 本リストの上から順ではなく、店のオペレーションの流れで:
   「入店 → 卓 → 注文 → 精算 → 締め」の基幹フロー (A-2,3,4,10,12) を最初に確定
2. **共通基盤 (D-1,2)** — 基幹フローの仕様が固まった時点でDB設計に着手 (先にDBを作ると手戻りする)
3. **LINE連携 (D-3 + B/C)** — 管理画面側の実データができてから接続
4. **施策系 (A-16〜19, E-1〜8)** — 基幹が回ってから
